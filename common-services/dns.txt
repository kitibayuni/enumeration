DNS ZONE TRANSFER
If a DNS server isn't configured correctly (limiting which IPs can perform a DNS zone transfer), then anyone can ask a DNS server for a copy of its zone information, thus grabbing MANY ip addresses and host names

DIG AXFR ZONE TRANSFER:
dig AXFR @ns1.inlanefreight.htb inlanefreight.htb


FIERCE FOR DNS ENUMERATION:
fierce --domain zonetransfer.me


DOMAIN TAKEOVER:
Domain takeover is registering a non-existent domain name to gain control over another domain; the same thing can happen with a specific subdomain


SUBDOMAIN ENUMERATION USING SUBFINDER:
./subfinder -d inlanefreight.com -v
(different from gobuster and ffuf because it uses DNS)


OR SUBBRUTE:
git clone https://github.com/TheRook/subbrute.git >> /dev/null 2>&1
cd subbrute
echo "ns1.inlanefreight.com" > ./resolvers.txt
./subbrute.py inlanefreight.com -s ./names.txt -r ./resolvers.txt
(better for local networks, since you can use local resolvers)

DNS MITM USING ETTERCAP
Attackers intercept communication by DNS Cache Poisoning using MITM tools like Ettercap/Bettercap

First, edit the /etc/ettercap/etter.dns file to map the target domain name.

Next, scart the Ettercap tool and scan for live hosts:
Hosts > Scan for Hosts.
Add target ip address to Target1
Add default gateway IP to Target2
activate dns_spoof in Plugins > Manage Plugins
Might need some configuration but this should reroute the traffic from the target to a different ip
